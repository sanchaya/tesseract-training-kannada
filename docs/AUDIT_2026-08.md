# Audit — August 2026

Record of defects found and fixed in one session, covering the rendering pipeline, the font registry
and the portal. Each entry gives the symptom as observed, the actual root cause, the fix, and how it
was verified.

**Headline:** two independent rendering defects were corrupting training data. Neither was visible in
the portal, and one had been masked for months by the reference font used to check for it.

| # | Area | Defect | Severity |
|---|---|---|---|
| 1 | Rendering | Forced Indic OpenType features reversed every conjunct in GTN/GMP/WMP | **critical** |
| 2 | Rendering | `generate-inventory.py` used bare Pillow — no shaping at all | **critical** |
| 3 | Fonts | New families invisible: directory names didn't match fonts.yml `id` | high |
| 4 | Fonts | Kittel (OTF-only) had zero inventory coverage | high |
| 5 | Portal | Phantom "Training is running in the background" banner | medium |
| 6 | Portal | Live Log permanently empty | medium |
| 7 | Pipeline | `03-train.sh` never wrote a log file | medium |
| 8 | Portal | Font registry reported the same image count for every font | low |
| 9 | Portal | Presence detected via `.git` — wrong for downloaded fonts | low |
| 10 | Portal | Hardcoded font lists in two API endpoints | low |
| 11 | Training data | Classical corpus rendered as pages, not lines — CTC could never align it | **critical** |
| 12 | Data prep | `02-make-lstmf.sh` resumed from cached `.lstmf` *before* validating — guards never ran | **critical** |
| 13 | Corpus | Legacy specimen grids with reserved codepoints survived cleaning; whole line unencodable | high |

## 1. Forced Indic features reversed conjuncts *(critical)*

**Symptom.** ~21 conjuncts (`ತ್ತ ದ್ದ ನ್ನ ಮ್ಮ ಲ್ಲ ಸ್ತ ಪ್ರ ಗ್ರ ತ್ರ ಶ್ರ ಸ್ವ ರ್ಕ ಕ್ಕ ಬ್ಬ ಷ್ಟ ಕ್ತ ನ್ಮ ಧ್ವ ಸ್ಪ ನ್ದ`, plus `ಕ್ಷ` in GMP)
rendered wrong in GTN, GMP and WMP. Kittel was fine.

**Root cause.** `shaping_render.py` passed `hb.shape()` a 23-tag feature dict including the Indic tags
`blwf half pref pstf vatu cjct rphf`. HarfBuzz's Indic shaper applies those itself, per glyph, via
internal masks. Forcing them enables them across the whole run, so below-base substitution also hits the
base consonant — the cluster reorders and the ottu is emitted **before** its base.

```
ತ್ತ   correct → uni0CA4 + kn_t_ottu
     forced  → kn_t_ottu + uni0CA4
```

**Why it survived so long.** Kittel's GSUB has only `blwf/blws/haln/psts` and no reordering triggers, so
it renders identically under every feature setting. It was the designated reference font, so every
comparison silently validated against the one font that could not exhibit the bug.

`docs/CONJUNCT_RENDERING.md` §7 had already derived the correct rule — *"do not use the full 24-feature
string, it overrides native Indic shaping"* — but applied it only to `browser_render.js`. The Python
path never got the same treatment.

**Fix.** `_KANNADA_FEATURES = {}`. `aalt` stays as the only explicitly-passed feature, per font from
fonts.yml. No font files needed changing.

**Verified.** 21 clusters × 4 fonts, asserting the ottu glyph never appears first: zero reversed.
Visual sheets in `tmp/conjunct-audit/`.

> **Glyph count is not a valid test.** 2 glyphs is *correct* for most Kannada conjuncts (base + ottu).
> All four fonts returned 2 both before and after the fix. **Order** is the discriminator.

## 2. Inventory generator had no shaping *(critical)*

**Symptom.** None visible — inventory images looked plausible at a glance.

**Root cause.** `generate-inventory.py` rendered with `ImageDraw.text()`, which does not run GSUB. Every
conjunct was drawn as separate codepoints. This is the character-baseline set for inventory-first
training and is almost entirely conjuncts, so it was the worst possible place for this defect.

Two further faults in the same file: `aalt` was never applied, and font discovery was a top-level
`fonts/*.ttf` glob that found only 2 stray files.

**Fix.** Routes through `shaping_render`; `aalt` read per font from fonts.yml; discovery made recursive
and `.otf`-aware, scoped by default to fonts.yml-declared weights (`--all-fonts` opts out).

**Verified.** 196 → 2,156 images across 22 weights. Kittel `ಕ್ಷ` shapes to 2 glyphs, not 3; mean pixel
delta 42.3 vs the old Pillow output.

## 3. New font families were invisible *(high)*

**Symptom.** Anek Kannada and Baloo Tamma 2 were added to fonts.yml but produced no gallery images, no
training images, and appeared nowhere in the OCR test.

**Root cause.** Every generator resolves fonts at `fonts/<id>/`. The folders were named `Anek_Kannada`
and `Baloo_Tamma_2`, so the lookups silently found nothing.

**Fix.** Directories renamed to `kan_anek` / `kan_baloo`. `scan_font_dir()` now scopes to the declared
`font_dir`, which also stops Anek's 5 width families (41 files) from producing 41 gallery variants —
`font_dir: static/AnekKannada` narrows it to the 8 intended weights. Variable fonts are skipped.

**Verified.** 8 Anek + 5 Baloo variants generate; existing families keep every variant (18 → 31 total).

> **Rule: the directory name under `fonts/` must equal the `id` in fonts.yml.** Nothing enforces this,
> and the failure is silent.

## 4. Kittel had zero inventory coverage *(high)*

Kittel ships OTF only. Inventory discovery globbed `*.ttf`, so a core historical font contributed
nothing to the character baseline set. Discovery now covers `.ttf` and `.otf`.

## 5. Phantom training banner *(medium)*

**Symptom.** "Training is running in the background" with no training running; step buttons locked.

**Root cause.** Two independent triggers behind `d._training || running === 'train'`:

1. `pgrep -x lstmtraining` also matches **defunct (zombie)** processes.
2. `runningStep` is cleared in the child's `exit` handler — which never fires if the spawn itself fails,
   and training is launched detached via `caffeinate`, so a killed wrapper or a portal restart mid-run
   left it stuck at `'train'` permanently.

**Fix.** Zombie filter via `ps -o stat=`; an `error` handler on the child; and `/api/status` reconciles
against the OS process table on every poll, clearing a stale `runningStep`. Live PIDs exposed as
`_trainingPids` for diagnosis.

---

## 6. Live Log permanently empty *(medium)*

**Symptom.** Banner said "watch the Live Log"; the panel showed nothing.

**Root cause.** The dashboard log panel is only opened inside `run()` — the handler for clicking a step
button *in that browser tab*. Training started from the terminal never opened it, and a page reload
mid-run had the same effect. The backend was fine throughout.

**Fix.** `attachDashLog()` — the status poll opens the panel for any detected run this tab didn't start,
backfills 40 lines from `/api/log/tail`, subscribes to the SSE stream, and releases cleanly on finish.

---

## 7. `03-train.sh` never wrote a log *(medium)*

**Symptom.** Live Log showed the *previous* run's final lines, frozen, and nothing under `logs/` updated.

**Root cause.** The script contained no logging. `logs/training.log` existed only because the usage line
told you to add `> logs/training.log 2>&1`. Run without the redirect, nothing was ever written.

**Fix.** Self-logging via `exec > >(tee -a logs/training.log) 2>&1` when stdout is a terminal. The portal
sets `TRAINOCR_NO_TEE=1` because `runBg` already points the child's stdout at that same file — without
the guard every line would be written twice.

## 8–10. Font registry inaccuracies *(low)*

| Defect | Cause | Fix |
|---|---|---|
| Every font showed the same image count (5,400) | `/api/fonts` returned `globCount(rendered/)` — the folder total — for all rows | Bucket per font by the `<id>_` filename prefix |
| Anek/Baloo showed "Not cloned" despite being present | Presence tested by looking for a `.git` dir; Google Fonts arrive as downloads | `hasFontFiles()` scans for actual `.ttf`/`.otf` |
| New fonts missing from gallery + OCR test | `["kan_gmp","kan_gtn","kan_kittel","kan_wmp"]` hardcoded in two endpoints | Both derive from fonts.yml via `fontFamilyIds()` |

The same `.git` assumption also made step ① Prep report `fonts 0/6` after the fonts folder was cleaned.

**Note on the "Degraded" badge.** Not a fault — it is the `degrade: true` flag, meaning letterpress
simulation (0.6 px blur, 0.3% speckle, ±0.8° rotation, deterministic per seed) is applied to the
historical revivals. The label is misleading and could be renamed.

## 11. Classical corpus was page-level, not line-level *(critical)*

**Symptom.** Training appeared stuck. The log repeated `Compute CTC targets failed for
…/vaddaradhane__kan_gmp_…/pageNNNN.lstmf!` and made no progress.

**Root cause.** `render-a5-pages.py` emitted one image per **page** with the whole page's text as a
single transcription. Tesseract LSTM training requires one image per **text line**. The LSTM scales
input to 48px height, so an 875×1241 page yields ~33 timesteps — but CTC needs at least one timestep
per label and the page carried ~700 characters. No alignment is possible, so the sample can never
train.

A second, independent error (`Can't encode transcription`) came from characters outside the expanded
unicharset — chiefly **ೞ** (U+0CDE) in 9,610 files, plus stray Latin letters, en dashes and Telugu
codepoints. That one is real but secondary; the CTC failure blocked everything.

**Verification.** Sampling 200 files per source:

| Source | Usable | Infeasible |
|---|---|---|
| `rendered/` (lines) | 200 | 0 |
| `inventory/` (chars) | 200 | 0 |
| `classical/` (pages) | **0** | **200** |

**Fix — two parts.**

1. **`--lines` mode** in `render-a5-pages.py` / `browser_render.js`. Chrome measures every wrapped
   line's box via per-character client rects after layout; the page screenshot is cropped to those
   boxes and each crop is written with exactly the text that produced it. Line crops measure ~875×55 →
   ~760 timesteps for ~46 characters, ~16× the CTC minimum. See
   [IMAGE_GENERATION.md §8](IMAGE_GENERATION.md).
2. **CTC feasibility guard** in `02-make-lstmf.sh`, rejecting any pair whose labels exceed the
   timestep budget before it reaches `list.txt` — so this class of defect fails loudly at data-prep
   time instead of silently stalling a multi-day training run.

**Status.** Crop path and geometry verified; the full `--lines` render has **not** yet been executed —
it needs Chrome and a multi-hour run on the 28,534 pages.

## 12. Validation ran after the resume shortcut *(critical)*

**Symptom.** The encodability and CTC guards logged **zero** rejections, yet
training still reported ~1,480 `Can't encode transcription` errors per 3,000 log
lines and the skip ratio sat at 23%.

**Root cause.** `_make_lstmf_impl()` returned an existing `.lstmf` immediately:

```python
    # Resume: already done
    if lstmf.exists():
        return str(lstmf.resolve())      # ← guards were BELOW this line
```

Nothing was regenerated, so nothing was validated. Every `.lstmf` built by an
earlier run — including all the ones built before the guards existed — was
re-admitted to `list.txt` unchecked. Measured: **1,675 of 11,444 entries (14.6%)
unencodable**.

**Fix.** Guards moved above the resume check; a rejected pair now has its stale
`.lstmf` / `.box` / `.png` deleted rather than left to be picked up again.
Resume no longer means "trust whatever is on disk".

**Lesson.** A cache that is checked before validation silently preserves every
defect that predates the validation.

## 13. Legacy specimen grids in the corpus *(high)*

**Symptom.** After the unicharset was expanded and training restarted, the skip
ratio went *up* — to 60.4% — with failures like:

```
Can't encode transcription: 'ಹ್ಕ ಹ್ಖ ಹ್ಗ … ಹ್಩ … ಹ್಴'
```

**Root cause.** `corpus/raw_kannada.txt` contains systematic consonant-cluster
grids left by an early version of the specimen generator, built by sweeping raw
Unicode ranges. They include the reserved codepoints ಩ (U+0CA9) and ಴ (U+0CB4).
The current `generate-specimen.py` uses curated lists and is not the culprit —
this is old data baked into the corpus file.

`clean-corpus.py` stripped the offending characters but **kept the line**, and
lstmtraining rejects a transcription as a whole: one bad cluster fails all 16
combinations on that row.

**Fix.** `clean-corpus.py` now verifies each cleaned line is actually encodable
against the live unicharset and drops it otherwise, reporting the count. 42
lines removed. Stripping characters is not the same as producing a trainable
line.

| `test-images/` | 1,764 | 3,038 | shaping fix + 2 new families |

**Training impact.** The Phase 2 run (iteration ~116K, BCER 1.056%) was trained against reversed
conjuncts and an unshaped inventory. Those images are now corrected, so training must restart from the
base model:

```bash
pkill lstmtraining
INVENTORY_DIR=inventory ./scripts/02-make-lstmf.sh
TRAIN_MODE=fresh caffeinate -i ./scripts/03-train.sh
```

Expect the lstmf count to rise (inventory 196 → 2,156; rendered 5,400 → 9,300) and early BCER to look
worse than 1.056% — that is the fresh output layer, not a regression.

## Process lessons

1. **A reference that cannot exhibit the bug validates nothing.** Kittel was immune to the feature
   forcing by construction. Every comparison against it passed. Pick references that are *sensitive* to
   the failure mode.
2. **"Is shaping present?" is not "is shaping correct?"** The first audit pass confirmed each path
   called `shaping_render` and moved on. The call itself was wrong.
3. **A rule written down for one code path does not propagate itself.** The correct feature policy was
   documented in `CONJUNCT_RENDERING.md` §7 and applied to Chrome, while the Python path did the exact
   opposite for months.
4. **Silent resolution failures are expensive.** A font folder whose name doesn't match its `id`
   produces no error anywhere — it simply renders nothing.
