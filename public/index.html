Learn how OCR training works

A complete guide to building a Tesseract model for historical Kannada documents

What is Tesseract training?

Tesseract is an open-source OCR (Optical Character Recognition) engine. At its core is an LSTM (Long Short-Term Memory) neural network that learns to convert images of text into characters.

The standard kan model was trained on modern digital Kannada fonts. When you scan a 19th-century book printed with mission press letterpress type, the shapes are different enough that the model makes many mistakes.

Fine-tuning starts from the existing kan model (which already understands Kannada grammar and conjuncts) and teaches it the new letterforms by showing it thousands of examples. The result is kan_hist — a model that handles historical typefaces without losing its understanding of modern Kannada.

The 6-step pipeline

Step 1
Prep base model
Downloads kan.traineddata from Tesseract's official tessdata_best repository and extracts the raw LSTM weights (kan.lstm). Also clones the Karnata font repositories from GitHub.
Step 2
Build corpus
Downloads GT text for training images. Wikisource is the preferred source — it contains human-proofread transcriptions of 19th-century Kannada books in the same letterpress typefaces we train on. Wikipedia is used as a supplement for modern vocabulary and glyph coverage.

③+ Specimen (optional but recommended) — generates a systematic coverage text: every consonant × matra combination, all common conjuncts, historical vocabulary, and 19th-century style sentences. Merges into the corpus so every character is guaranteed to appear in training across all fonts.
Step 3
Render images
Uses Python (Pillow) to render each corpus line in each Karnata font style. Historical/letterpress fonts get blur + noise + slight rotation to simulate real ink-on-paper. Outputs PNG + matching .gt.txt.
Step 4
Generate lstmf files
Tesseract reads each PNG+GT pair and produces a binary .lstmf file containing the encoded training signal for the neural network. This step also picks up any real scans you've added via the Scan upload tab.
Step 5
Train
Runs lstmtraining for up to 400,000 iterations (default). BCER (character error rate) should fall steadily. Safe to stop any time — re-running this step resumes from the rolling checkpoint automatically, preserving full optimizer state. Note: --max_iterations is an absolute count, not relative — so resuming from a high iteration with a low limit will exit immediately.
Step 6
Package
Selects the best checkpoint, exports it, and combines it with Kannada language data to produce the final kan_hist.traineddata file — ready to drop into your Tesseract tessdata folder.

Corpus sources — where the training text comes from

The corpus is the text that gets rendered into training images. Quality and relevance matter: a model trained on 19th-century Kannada text will generalise far better to historical documents than one trained on modern web prose.

📖
Kannada Wikisource
Preferred source

kn.wikisource.org contains scanned Kannada books with human-proofread transcriptions. Pages are quality-rated:

⭐⭐ Validated (quality 4) — reviewed by two people
⭐ Proofread (quality 3) — reviewed by one person
Quality 1–2 pages are excluded
python3 corpus/download-wikisource.py --pages 3000
~80 MB dump · cached · reusable
📰
Kannada Wikipedia
Supplement

Modern Kannada prose — useful for Unicode glyph coverage and modern vocabulary. Less relevant than Wikisource for historical typeface training, but adds breadth.

python3 corpus/download-wiki.py --lines 5000
~150 MB dump · cached · reusable
📄
Your own text
Custom corpus

Transcriptions from books you've OCR'd, Sanchaya collections, or any Kannada text relevant to your documents. Place the text in corpus/raw_kannada.txt and run the clean step.

# write lines to corpus/raw_kannada.txt
python3 corpus/clean-corpus.py
Why historical text matters: The Karnata fonts are revivals of German Mission Press, Wesleyan Mission Press, and Basel Mission Press typefaces from the 1830s–1900s. Many Wikisource books were typeset in these exact presses. Training on proofread transcriptions of those books means the model learns the specific character shapes, conjunct forms, and ligatures of the typefaces it will encounter in the wild.

Reading the BCER chart

BCER (Byte Character Error Rate) is the percentage of characters the model gets wrong on its training data. Lower is better.

A healthy training run looks like a steep curve that gradually flattens. Stop training when BCER has stopped reaching new lows for around 10,000 iterations.

Note: BCER on synthetic training data is not the same as accuracy on real historical scans. A BCER of 1.5% might correspond to 5–8% on real documents — which is still dramatically better than the ~25% you'd get from the base kan model on these typefaces.

BCER > 10%
Early training. Normal — the model is still adjusting.
BCER 3–10%
Converging. Keep training, check for a plateau.
BCER 1–3%
Strong. Package and test on real scans.
BCER < 1%
Excellent. Verify it generalises on held-out scans.

Tips for historical documents

📷 Scanning
Scan at 300 DPI or higher. Grayscale is fine — no need for colour. Avoid shadows; use a flat-bed scanner where possible. For bound books, a book scanner prevents warping.
✍️ Ground truth quality
Transcribe exactly what you see — including archaic spelling, missing punctuation, and any unusual ligatures. Even 20 high-quality scan+GT pairs dramatically improve the model over synthetic data alone.
📐 Crop for training
Crop scans to single text blocks or paragraphs. Avoid mixed-column pages or pages with decorative borders — those confuse the training signal. Simple, clean blocks of body text work best.
⏱ When to stop training
Stop when BCER has not reached a new best for ~10,000 iterations. Beyond that, the model starts memorising training images and performs worse on real scans — this is overfitting. Use the checkpoint browser to package an earlier, better checkpoint.
🔍 OCR test — three modes
The OCR test tab has three sub-modes (tabs at the top of the panel):
• Single image — drop any Kannada image; kan and kan_hist run in parallel; paste ground-truth text to get live CER/WER; export result as .txt.
• Batch — select multiple images, OCR all at once, view results in a table, export as CSV.
• Wikisource — paste a kn.wikisource.org page URL; fetches the human-proofread text and runs OCR side-by-side for direct comparison.

Tip: always compare kan vs kan_hist on the same image to measure the improvement your training has achieved.
🔤 Kannada Unicode Reference & per-font image testing
Scroll to the bottom of the OCR test tab to find the Unicode Reference panel.

Font tabs — select a font family (GTN, GMP, WMP, Kittel). Each font has TTF and OTF variants selectable from the dropdown — both formats are used for training to capture any rasterisation differences.

Live preview — characters are rendered directly in your browser using the actual font file served from /fonts/ via @font-face. No images needed — switch fonts and variants instantly.

Generated PNGs — click Generate images to run scripts/gen-char-images.py (Pillow) which writes one PNG per character to test-images/<font>/<variant>/. Switch to PNG view to see exactly what Tesseract sees during recognition — the actual rasterised pixels.

1:1 OCR test — appears after images are generated. Runs Tesseract.js on every character PNG and marks each cell ✓ green (correct) or ✗ red (shows what was returned instead). Results export as CSV per variant. Use this to identify specific characters or conjuncts where the model needs more training data.
➕ Adding a new font
Edit fonts.yml — add the font's repo URL, font_dir, and list each file under font_files. Include both .ttf and .otf if the font ships both — the server registers them as separate training variants automatically.

Set degrade: true for historical/letterpress typefaces (adds ink-spread blur + noise). Set degrade: false for clean modern fonts.

Then re-run: Prep base → Render images → Make lstmf → Train. Training resumes from the last checkpoint, so no earlier work is lost.
⚠️ Unicharset limitation
The base kan.traineddata unicharset (140 entries) is missing five archaic Kannada codepoints: ಋ ಙ ಝ ಞ ಱ. Ground-truth files containing these as standalone characters cause a "Can't encode transcription" error during lstmf generation.

The pipeline filters them automatically. If you supply your own corpus, scan for these characters before running Make lstmf. The conjunct ಜ್ಞ works correctly — only the standalone codepoints are affected.
⚠️ 1:1 character test caveat
Tesseract is a line-level model — it expects a full line of text, not isolated characters. Testing individual character images (the 1:1 OCR test) always shows more errors than the model makes on real line images because it lacks the surrounding context it was trained with. Use full-line or Wikisource tests for a meaningful accuracy measurement of your trained model.

Known limitations of this approach

BCER ≠ real-world accuracy
BCER is measured on clean synthetic training images. Real-world CER on degraded historical scans is typically 3–5× higher. A BCER of 1.5% may correspond to 6–10% CER on actual letterpress pages depending on paper quality, ink spread, and scan resolution. Always test on held-out real scans before declaring the model ready.
Fine-tuning scope
Fine-tuning from kan.lstm is constrained to the existing unicharset — you cannot add new characters without retraining from scratch. This is the right tradeoff for this project (5 archaic chars excluded, everything else preserved), but means kan_hist cannot recognise characters the base model does not know.
Synthetic vs. real training data
Most training images are synthetically rendered — digitally degraded to simulate letterpress. Even a small number of real scanned pages with careful ground truth significantly outweighs synthetic data for accuracy on real documents. Adding real scans via the Scan upload tab is the single highest-value improvement you can make after initial training.
max_iterations is absolute
Tesseract's --max_iterations flag counts from iteration 0, not from the resume point. If you resume from iteration 183,000 with --max_iterations 200,000, training runs only 17,000 more steps. The default of 400,000 avoids this for normal workflows, but keep this in mind if you run many training sessions or need to run beyond 400,000 iterations.

Glossary

The fraction of character bytes the model transcribes incorrectly on its training data, expressed as a percentage. Lower is better. 1% BCER means 1 wrong character per 100. Note that this is measured on synthetic training data; real-world CER on scanned documents is typically higher.
A type of recurrent neural network used by Tesseract 5. Unlike older template-matching OCR, LSTM can remember context across a line of text — important for recognising Kannada conjuncts (stacked characters) and vowel marks that depend on nearby letters.
A .traineddata file contains everything Tesseract needs for one language/style: the LSTM weights, language model (word lists, n-grams), and Unicode normalisation tables. Copy it to your tessdata directory and Tesseract can use it immediately.
Tells Tesseract how to expect text to be laid out. PSM 3 (auto) tries to detect columns and paragraphs. PSM 6 assumes a single uniform block of text — best for cropped paragraphs. PSM 7 treats the whole image as a single text line — best for testing individual lines.
A plain-text file containing the exact correct transcription of the corresponding image. The filename must match the image (e.g. page01.gt.txt for page01.png). Ground truth quality is the single biggest factor in model quality — errors in GT become errors in the model.
An intermediate binary format produced by tesseract … --psm 6 lstm.train. It encodes both the image features and the ground truth in the format lstmtraining expects. Generated automatically by the make-lstmf step.
Training from scratch requires millions of examples and days of compute. Fine-tuning starts from an existing model (here: kan.lstm) that already knows Kannada and just needs to learn new letterforms. It typically converges in hours with thousands of examples instead of millions.
Every 100 iterations, lstmtraining saves two things: a named checkpoint file (kan_hist_<BCER>_<iter>.checkpoint) recording BCER and iteration in the filename, and the rolling checkpoint (kan_hist_checkpoint). The rolling checkpoint is updated on every save and always reflects the most recent training state including optimizer momentum — making it the correct file to resume from. Named checkpoints let you go back to a specific earlier point (useful if the model overfit after a plateau).
The unicharset is the list of Unicode characters (and multi-character clusters like virama combinations) that a trained model can output. It is fixed at training time and cannot be extended by fine-tuning alone. The base kan.traineddata unicharset has 140 entries and does not include five archaic Kannada codepoints (ಋ ಙ ಝ ಞ ಱ). Ground-truth files containing these cause a "Can't encode transcription" error during lstmf generation; the pipeline filters them automatically.
The percentage of characters that differ between the OCR output and the ground truth, calculated using Levenshtein (edit) distance. Distinct from BCER: CER is measured on real held-out images (scans or rendered test lines), while BCER is measured on training data internally by lstmtraining. CER on real scans is always higher than BCER on training data — typically 3–5× for well-trained models on historical material.
CER measures the edit distance (insertions + deletions + substitutions) between OCR output and reference text, divided by reference length. WER does the same at the word level. Used in the OCR test tab to compare model outputs against ground truth you paste in.
Historical fonts (degrade: true in fonts.yml) are rendered with: Gaussian blur (simulates ink spreading into paper fibres), salt-and-pepper noise (paper grain, foxing), and a slight random rotation (print misalignment). This makes the synthetic images look more like real letterpress scans so the model generalises better.
Kannada Wikisource (kn.wikisource.org) uses the ProofreadPage extension to quality-rate each transcribed page. Level 3 (Proofread) means one volunteer has read and corrected the text against the scan. Level 4 (Validated) means a second volunteer has independently verified it. Only levels 3 and 4 are used for corpus building — lower levels may contain uncorrected OCR errors that would harm training quality.
The corpus is the pool of Kannada text lines that get rendered into PNG training images. It must cover the full Unicode Kannada block (U+0C80–U+0CFF), including conjunct consonants formed with the virama (U+0CCD). A corpus sourced from historical books is preferable for kan_hist because it reflects actual vocabulary and typographic patterns the model will encounter on real historical scans. Wikipedia is added only as a supplement for glyph coverage.
In Kannada (and all Brahmic scripts), two consonants can be written as a single stacked glyph called a conjunct. The virama (ಹಲಂತ, U+0CCD) is an invisible combining character placed after the first consonant to suppress its inherent vowel and signal the stack. For example: ಕ + ್ + ತ → ಕ್ತ. Tesseract must learn these multi-codepoint sequences as single visual units. The Unicode Reference panel in the OCR tab shows all 24 common conjuncts used in training.
TrueType (.ttf) and OpenType/CFF (.otf) are two formats for the same underlying typeface design. They differ in how glyph outlines are mathematically described. When rasterised to pixels, small differences appear at low resolutions. TrainOCR uses both formats for fonts that provide them, giving the model slightly different pixel patterns and improving robustness on real scanned material.
The Unicode Reference panel renders characters in the browser using CSS @font-face — the actual TTF or OTF file is served from /fonts/ and loaded directly by the browser. You see the exact glyph shapes of the historical typeface in real time, with no server processing. Compare this to PNG mode, which shows what Pillow rendered at 150 DPI — exactly what Tesseract sees during training.
